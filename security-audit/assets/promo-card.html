security-audit

Audit, then a plan, then the fixes — and it stops to ask between each one.

v0.2.2
go · php · laravel · node · bun

How it runs

01

Audit

/security-audit

Runs the project’s own dependency audit, then greps the high-signal classes. One ranked table, ten rows at most, every row an openable path:line.

asks before writing anything
02

Plan

Writes docs/security-audit/<date>-plan.md — CRIT and HIGH only, findings table embedded, fix order where one finding enables another.

asks before touching code
03

Build

One finding, one edit. Each closed fix is verified by a real command — a build, the test suite, a request that used to succeed and now returns 403.

ANT-2026-001 CRITICAL OPEN SAMPLE

Session token accepted without signature verification

Affected component
api/auth/session.ts
Category
Authentication
First observed
2026-08-11
Description

The session middleware decodes the JSON Web Token supplied by the client and reads the user identifier from its payload, but the verification call that would check the token's signature is commented out. Any request carrying a syntactically valid token is treated as authenticated.

Business impact

Account access does not depend on a credential the service can verify. Anyone able to construct a token can act as any user of the application.

Evidence
api/auth/session.ts:41 const claims = jwt.decode(raw); // decode only // const claims = jwt.verify(raw, SECRET); ← verification disabled Observed: no call to jwt.verify or equivalent on any code path reaching requireSession(). Control absent.

Observed in source during review. No request was sent to a running system and no exploitation was attempted.

Remediation

Restore signature verification on every path that reads session claims, and reject tokens that fail verification rather than falling through to the decoded payload. Add a test that asserts a token signed with the wrong key is refused.

References
CWE-347 OWASP A07:2021 — Identification & Authentication Failures
ANT-2026-007 MEDIUM DEFERRED SAMPLE

Upload endpoint has no request size or rate limit

Affected component
services/media/upload.py
Category
Resource control
First observed
2026-08-12
Description

The upload handler streams the request body to disk without a declared maximum size, and no rate limit is configured for the route in the application or the reverse proxy configuration included in scope.

Business impact

A single authenticated client can consume storage and request capacity without a limit defined anywhere in the assessed configuration.

Evidence
services/media/upload.py:88 while chunk := await request.stream.read(65536): dest.write(chunk) # no cumulative size check deploy/nginx.conf — no client_max_body_size, no limit_req directive. Control absent.

Absence of a control, observed in the assessed source and configuration. Runtime limits set outside the assessed material, if any, were not visible to this review.

Remediation

Declare a maximum request size at the proxy and enforce a cumulative byte limit in the handler. Apply a per-account rate limit to the route.

References
CWE-770 OWASP A04:2021 — Insecure Design

B — Severity definitions

CRITICAL A control that protects accounts, funds, or personal data is absent or bypassable on a path reachable by an ordinary user. Address before release.
HIGH A significant weakness that requires a specific condition, role, or sequence to matter. Address in the current cycle.
MEDIUM A missing or weak control with limited reach, or one mitigated elsewhere in the assessed material. Schedule.
LOW Hardening or hygiene. No direct path to harm was identified in this review.
INFORMATIONAL An observation recorded for the reader's awareness. Not a defect.

C — Status definitions

OPENReported and not yet resolved.
FIXEDA change was made and re-reviewed against the same material.
ACCEPTEDThe client has accepted the risk in writing. Recorded, not resolved.
DEFERREDScheduled for a later cycle. Still open.

D — What this report does not contain

No CVSS score or vector is given. This assessment reads code and configuration; it does not run exploits or measure attack complexity, so any score would be a fabricated figure in a standard's notation. Severity labels above are reviewer judgements against the definitions in Appendix B.

Evidence quotes only what was observed — a file and line, a tool's own output, or the absence of a control. It is not a proof of concept and does not demonstrate a working attack.
